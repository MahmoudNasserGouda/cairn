# Testing guide

How Rujoom is tested, and the rule that comes before the rest: **a feature's tests are
written before the feature.** Decision:
[ADR-0022](adr/0022-ci-cd-is-mandatory-infrastructure.md); this is the working detail.

## The contract

1. **Tests first.** A new engine, parser or service lands its test file — with the cases
   it must satisfy, failing — before the implementation. For pure libraries this is cheap
   and it is where the design actually happens.
2. **A bug fix needs a test that fails without the fix.** Verify that by *reverting the
   fix and watching it go red*, not by assuming. This convention already exists in
   PROJECT_GUIDE; it is repeated here because it is the one most often skipped.
3. **No feature merges with its wiring untested.** The 2026-09-11 audit found twelve
   wiring-layer bugs — including one that disconnected GitHub whenever a second identity
   was added — behind a green `npm test`, because only `libs/**` was collected. That is
   what the `app` project exists to prevent.
4. **A refused behaviour is a test.** "We do not read `Connections.csv`"
   ([ADR-0029](adr/0029-linkedin-data-export-archive-import.md)), "the app CSP never gains
   `wasm-unsafe-eval`" ([ADR-0028](adr/0028-ocr-and-document-vision-sandbox.md)), "a
   manual edit survives a re-import"
   ([ADR-0031](adr/0031-profile-v2-provenance.md)) — each is an assertion, not a sentence
   in a document.

## Layout

`vitest.config.ts` runs two projects:

| Project | Environment | Collects | For |
|---|---|---|---|
| `libs` | node | `libs/**/*.test.ts` | pure engines, parsers, clients |
| `app` | jsdom + Angular `TestBed` | `apps/**/*.test.ts`, `api/**/*.test.ts` | services, components, the `cairn-auth` Worker |

```bash
npm test            # both projects + coverage
npm run test:watch  # watch mode
npm run verify      # format + lint + typecheck + test + CSP guard
```

Test files are typechecked via `tsconfig.test.json` — they are code, and code that is not
typechecked drifts.

## How each layer is tested

**Pure engines** (`libs/scoring`, `libs/matching`, `libs/discovery`,
`libs/repository-analysis`, `libs/issue-analysis`, `libs/doc-layout`, `libs/cv-parse`) —
no IO, no clock, no randomness. Tested as tables of input → expected output, with inline
snapshots for score breakdowns. A weights change means bumping `WEIGHTS_VERSION` and
updating snapshots **on purpose**; a snapshot updated reflexively is a test deleted.

**Parsers** (`libs/cv-extract`, `libs/cv-parse`, `libs/linkedin-archive`, `libs/zip`) —
driven by the synthetic fixture corpus below. Every parser also has hostile-input tests:
truncated, oversized, wrong magic bytes, lying headers, entry-count bombs.

**API clients** (`libs/github`) — `fetch` is stubbed. Cover the cache hit, the ETag 304,
the rate-limit floor per resource, the 429 backoff, the stale-on-error path, and the
dedupe of concurrent identical requests.

**Angular services** — tested through their public signals against `TestBed`, with
IndexedDB and `fetch` stubbed. Assert observable state, not internals.

**Components** — tested through inputs and rendered output. Assert what the user can see
and do: that an empty state appears, that a control is disabled, that a value round-trips
through an edit. Not CSS.

**Feature flags** — both states. `FEATURES.ai` off must render no AI control anywhere;
on must render them ([ADR-0033](adr/0033-ai-capability-frozen.md)). A flag tested in one
state is a flag that breaks in the other.

## Fixtures: synthetic only, never real

**No real CV, no real LinkedIn archive, no real user data enters this repository** — they
are PII, and a fixture is forever. Every fixture is generated by code, following the
pattern already in `libs/cv-extract/src/__fixtures__/build.ts`, so it is reviewable as a
diff and regenerable.

The corpus:

| Fixture | Exercises |
|---|---|
| single-column CV | the baseline path |
| two-column CV | column detection; must not interleave |
| bulleted roles | bullets staying attached to their role |
| right-hand date column | dates re-joined to their row |
| non-Latin text (**DOCX**) | encoding, RTL, and that the taxonomy does not false-positive. DOCX rather than PDF on purpose: a PDF in a base-14 font is single-byte encoded, so Arabic would need an embedded font and a ToUnicode CMap — which would test the fixture builder, not the parser |
| image-only (scanned) PDF | the `empty: true` path and the OCR sandbox |
| oversized / zip-bomb / truncated | failing closed |
| LinkedIn archive | the read allowlist **and** the refused-file assertions |
| GitHub GraphQL response | profile fragment construction |

## Coverage

Gate: **70%** statements / branches / functions / lines over `libs/*/src`,
`apps/web/src/app` and `api/**/src`, enforced in CI.

New libraries introduced by the current plan — `libs/doc-layout`, `libs/cv-parse`,
`libs/linkedin-archive`, `libs/zip` — carry **85%**. They are pure and fixture-driven, so
there is no excuse, and they are where a silent regression would be least visible.

Coverage is a floor, not a goal. Four files are excluded because they cannot run under
jsdom — each import's `*.worker.ts` and its `worker-url.ts`, which exist to hold the
`new Worker(new URL(...))` literal the bundler needs. Each is exercised by its import
tests' worker stub, and the Trusted Types policy they share is covered directly in
`core/worker-policy.test.ts`. Every exclusion is listed with its reason in
`vitest.config.ts`, and any new one needs the same treatment: a reason, in the config,
next to the exclusion.

## The Angular compiler is part of the harness

`vitest.config.ts` runs `@analogjs/vite-plugin-angular` over **both** projects. Without
it, Vitest runs Angular in pure JIT, which learns a component's inputs from decorator
metadata — so **signal inputs (`input()`, `model()`) do not bind at all**, by template
attribute or by `componentRef.setInput`. There is no error and no warning: the input
keeps its default and the component renders as if the caller had passed nothing.

Three things keep it working, and each is easy to undo by accident:

- `tsconfig.vitest.json` sets **`noEmit: false`**. Our base config sets `noEmit: true`,
  which is right for a typecheck and leaves the Angular compiler with nothing to emit.
- The TestBed setup lives at `apps/web/src/test-setup.ts`, **inside** that program. It
  used to be in `scripts/`, where the compiler could not see its `@NgModule` and emitted
  broken output that failed every test file in the project.
- The plugin is declared at the **root**, not on the `app` project, because both
  projects transform `libs/*`. One plugin and one esbuild meant the same file was
  instrumented two different ways and the merged coverage report could not align them.

`apps/web/src/test-harness.test.ts` asserts all of this directly. If it fails, that is
the cause.

## What is not unit-tested, and how it is covered instead

- **The CSP itself** — `scripts/check-csp.mjs`, run by `npm run verify` and CI.
- **The design-token contract** — `scripts/check-tokens.mjs`, also in `npm run verify`.
- **Bundle origins** — `scripts/check-bundle-origins.mjs`.
- **Dependency licences** — `scripts/check-licenses.mjs`.
- **The OCR sandbox's real isolation** — asserted by hand in a browser (the opaque frame
  cannot reach `sessionStorage` or IndexedDB) and by the CSP guard in CI. The
  `postMessage` protocol itself is unit-tested against a stub frame.
- **Visual appearance** — by eye, at desktop and mobile widths, in both themes. The
  token-contract test ([ADR-0032](adr/0032-design-system-and-information-architecture.md))
  catches a *missing* token, not an ugly one.
